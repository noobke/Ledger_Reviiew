台账审查工具 · 复审与优化方案

针对第 27 项误判、手写识别错误、N/A 与勾选错误、签名误识别、站点/设备分类问题，给出根因、开源选型与分阶段改造方案。

复审结论：可用但未达生产级 基线 v1.0 2026-11-25 含 GitHub 选型

1一页纸结论

v1.0 已经跑通“导入 → 拆页 → 分类 → 勾选/漏签 → 导出”的主链路，但真实台账上的误报仍然偏多，主要集中在四类根因，而不是单点 bug：

根因层表现性质
表格几何第 27 项双倍高行导致 27/28/30 误判；N/A 落到相邻行算法问题，可确定性修复
OCR 能力第 N 次、日期、设备编号、手写姓名读不出；N/A 未识别引擎能力问题，需换/补 OCR
签名口径客户签名被强行归属；维保签名候选错产品口径 + 模型能力
数据组织没有“线路 → 站点 → 垂梯/扶梯 → 梯号”的层级信息架构问题，改动可控
复审结论 拆页、分类、导出、漏签“有没有签”已经可用；勾选完整性在普通行上可用，遇到双高行会偏；手写字段与签名归属目前只能算“辅助候选”，不能作为自动结论。建议按 P0（2 周内）先修表格几何、N/A、客户签名、设备号规则与归档层级，再按 P1 换 PP-OCRv5 并补签名样本。

2问题复现与根因

以下页 15 / 页 5 的截图与材料中的 43 页样本一致（第 22 次、第 5 次，设备 LN60-071722-028）。可直接在样本上复现。

2.1 第 27 项“空位较大”被误判，连带 28/30 误判

现象

  • 第 27 项“层门锁钩锁”行高约为普通行的 2 倍；
  • 系统报“第 27 项未填写”，并连带把 28、30 判成空白；
  • 页 5 同时出现 1、28、30 三项空白。

根因

  • CheckReader.DetectRows 用“等间距窗口”评分选行线；遇到双高行，等间距假设被破坏，窗口会跳线；
  • 行带错位后，按“项号 → 行号”映射，27 之后的项整体偏移；
  • 结果列固定 x 范围，但行带 y 偏移，导致勾选落在相邻行。

修复方向改用“形态学横线检测 + 行带合并”，不再假设等间距；双高行按高度中位数识别并保留为一个行带。标记检测改为“先找墨迹连通域，再按 y 中心归入行带”，而不是先算行高再切格。

2.2 N/A 识别错误

  • N/A 是**印刷文字**（如第 1、17 项），不是手写勾选；当前只做墨迹比例，把 N/A 当“已填”，或行偏移后把 N/A 算到相邻项。
  • 部分表单是手写圈住 N/A；需要同时识别“印刷 N/A 文本”和“手写圈 N/A”。
  • 规则层没有“N/A 是合法结果”的显式状态，A1 只区分 FILLED/BLANK。

修复方向结果列做一次小区域 OCR/模板匹配，识别 N/A、无此项、／；CheckItem 增加 NA 状态；A1 只在 BLANK 时报警。

2.3 手写第 N 次 / 日期 / 设备编号识别失败

  • Windows.Media.Ocr 对印刷体可靠，对连笔手写基本不返回文字；当前 ExtractFields 依赖整页 OCR 文本 + 正则，手写字段天然为空。
  • 设备编号正则只认“三段连字符”格式，HK09102、HK09102(N) 被 C2 判为格式异常。
  • 日期正则只认 2026.8.18 这类带分隔符的写法，OCR 可能输出 2026818 或带空格的形式。
  • 没有“字段区域 OCR + 语法约束 + 置信度”的链路，只有整页文本兜底。

修复方向字段级高分辨率 OCR（日期/编号/第 N 次各自裁区域，2–3 倍上采样）+ 语法解码（日期、序号、设备号、运行次数）+ PP-OCRv5 手写增强；读不出时明确“待人工确认”，不猜测。

2.4 客户签名被“乱识别”

  • 当前对所有应签位置都调用 SignatureEngine.MatchSlot，包括 CUSTOMER。
  • 客户没有字迹基准，强行在 20 人维保人员表中找最像的人，必然出现“施俊杰 49 分”这类结果。
  • 候选列表还出现 NaN，是空特征/空候选序列化后的显示问题。

修复方向客户/第三方签名只校“有墨迹/无墨迹”，不做归属；维保人员签名才做候选+人工；修复 NaN 过滤与候选为空时的 UI。

2.5 维保人员签名候选不准

  • 字迹表留一法 Top-1 约 76%，但真实单据签名与字迹表存在扫描分辨率、笔画粗细、倾斜差异，域偏移明显；
  • 两个签名在同一框内时，切分依赖投影，容易切错或合并；
  • 描述子是手工特征，不是学习型签名模型，跨域泛化有限。

修复方向短期保持“候选+人工”，但改进切分与归一化；中期用 200–300 份带姓名标注的真实签名微调 SigNet/TrOCR 类模型，并做阈值校准。

2.6 分类与归档层级缺失

  • 当前只有批次的“站点/设备编号”两个自由文本，没有“线路 → 站点 → 垂梯/扶梯 → 梯号”的固定层级；
  • 导出目录是“站点/设备/类型”，缺少“垂梯/扶梯”一层；
  • 多个批次之间没有档案视图，无法按站汇总；
  • 站点名称靠批次输入，表单上的手写项目名称读不出，无法自动归站。

修复方向增加线路/站点主数据、设备类型（垂梯/扶梯/自动人行道）、设备编号三个结构化字段；UI 按“站点 → 类型 → 梯号”分组；导出目录同步。

6P0：表格与勾选重写

目标：解决第 27 项、28/30 连带误判、N/A 错误，做到“每一行有明确的行带，每一个标记有明确的归属”。

6.1 新算法

  1. 横线检测：用 OpenCV 形态学（水平核 1×40）提取横线，得到每半表的线中心；不再用“行暗像素比例 + 等间距评分”。
  2. 行带合并：计算相邻线间距的中位数；把明显大于 1.5 倍中位数的带标记为“双高行”，但保留为一个行带；确保行带数 = 模板项数。
  3. 标记检测：在结果列 x 范围内做连通域，过滤表格线/噪声；按连通域中心 y 归入行带；一个行带内任意标记 = 已填。
  4. 标记分类：用轻量分类器区分 ✓ / ○ / × / N/A / 其他；N/A 既可能是印刷字，也可能是手写圈。
  5. N/A 文本：对结果列做小区域 OCR（白名单 N/A、无此项、／），命中即 NA。

6.2 规则调整

  • CheckItem.Result 增加 NA；A1 只对 BLANK 报警。
  • 模板包增加 naItems（如垂梯半月 1、17），A4 用它判断“应 N/A 却填了勾”或“应实测却填 N/A”。
  • 行带无法确定时，报“表格结构无法识别”，而不是逐项报空白。

6.3 验收

  • 页 15：27/28/30 判定与人工一致；页 5：1/28/30 与人工一致。
  • 43 页样本：A1 误报 ≤1 项/册；N/A 项不再报空白。
  • 对 20 份真实单据做人工对照，勾选一致率 ≥98%。

7P0：字段 OCR 与语法解码

7.1 字段区域

字段定位方式解码规则
第 N 次标题“第 __ 次”区域；固定比例 + 标题锚点阿拉伯数字/中文数字；范围 1–200；与同设备序列校验
日期“日期”锚点下方的签名区；或页脚日期支持 2026.8.18、2026-8-18、2026年8月18日、2026818；范围校验；未来日期排除
设备编号WBS/电梯编号行；或“当地编号/使用单位编号”允许 HK09102、HK09102(N)、LN60-071722-028、E3900-501-102；统一大写与去空格
运行次数页脚“运行次数”数字 3–7 位；与上一期比较单调性
站点项目名称行；读不出时用批次站点与站点主数据做模糊匹配（编辑距离）

7.2 OCR 引擎

  • 已实施：RapidOcrNet + PP-OCRv5（Apache-2.0），CPU 本地推理，模型随安装包分发；Windows OCR 保留为 fallback。
  • 字段裁切 2–3 倍上采样、灰度/对比度增强、去黑边；日期单独做 450dpi 级裁切（参考 chinese-handwriting-ocr 的做法）。
  • 每个字段输出：原文、规范化值、置信度、来源区域；低置信进入“待人工确认”。
  • 不把 OCR 文本直接当结论；规则只消费“高置信 + 通过语法校验”的值。

7.3 验收

  • 在 50 页真实样本上建立字段基线：日期、第 N 次、设备编号各标注 50 个；
  • 目标：清晰手写日期 ≥80%、设备编号 ≥85%、第 N 次 ≥80%（达不到则保持“待人工确认”，不强行自动化）。

8P0：签名口径修正

角色v1.0v1.1
客户/使用单位也做归属比对，出现“施俊杰 49 分”只校“有/无墨迹”，不显示候选人，不报“不是本人”

8.1 中期模型

  • 收集 200–300 份真实单据上的维保签名，人工标注姓名；
  • 用 SigNet 类度量学习或 TrOCR-Chinese 做微调（注意许可证）；
  • 留一法/跨单据验证，目标 Top-1 ≥90%、误配 ≤1%；达不到就保持“候选+人工”。

13风险与决策

风险/决策说明建议
手写 OCR 上限即使 PP-OCRv5，连笔日期/编号也不可能 100%产品上保留“无法辨认/待人工确认”，不追求全自动
签名模型许可证TrOCR-Chinese 未声明许可证优先 Apache-2.0 的 PP-OCR/RapidOCR；签名模型自训或选可商用权重
站点主数据没有站点清单无法保证“按站分好”先做可配置站点表，后续导入标准清单
双高行/合并单元格表格结构变化多行线 + 行带合并；无法确定时整表报“结构无法识别”
性能PP-OCRv5 + 字段 OCR 会增加耗时只对字段区域做 OCR，整页 OCR 降频；缓存
包体ONNX 模型增加 20–60MB模型随包分发，保持离线；可分离可选包
